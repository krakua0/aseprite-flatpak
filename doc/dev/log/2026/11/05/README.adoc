== Fixed: runtime-version quoting

* Symptom: `runtime-version: "25.08"` (double quotes, committed form) vs hard-coded `'…'` in `bump_edit.py`, `build.sh`, `bump.sh`. The runtime edit never matched, so the runtime pin was never updatable.
* `bump_edit.py`: pattern is quote-agnostic — `runtime-version: (?P<q>["'])[0-9.]+(?P=q)`; the replacement reuses `(?P=q)`, so the file keeps its own quote style.
* `build.sh`, `bump.sh`: quote-free two-stage reader — match `^runtime-version:`, then extract `[0-9]{2}\.[0-9]{2}`.
* Manifest left as-is: both quoting forms are valid YAML, and `yq` rewrites scalars to double quotes.

== Fixed: flathub runtime discovery

* `flatpak remote-ls` output is TAB-separated `name / id / version / branch`; the name contains spaces (`Freedesktop Platform`), so the old whitespace-FS `awk '$2==r {print $3}'` never matched and fell through to `RUNTIME_FALLBACK`. Field 3 is the SDK version (`freedesktop-sdk-26.08.1`), never a branch.
* Now: `awk -F'\t' '$2 == id { print $NF }'`.
* `remote-ls` needs an explicit installation, otherwise it aborts with *"Remote 'flathub' found in multiple installations"*. Both readers try `--system`, fall back to `--user`.

== Changed: runtime selection is constraint-aware

* Rule: newest branch published for `org.freedesktop.Platform` *and* for every `sdk-extensions:` entry of the manifest.
* Reason: `org.freedesktop.Sdk.Extension.llvm20` is published only up to `25.08`; `26.08` carries llvm21/llvm22. Plain "latest Platform branch" would pin an unbuildable manifest.

== Changed: `--check` covers the full edit set

* `bump.sh --check` previously ran `--skia-only` + `--dry-run`, so pattern drift surfaced only when files were written.
* Now `--check` runs the same edits as a real run, with `--dry-run` appended. `bump_edit.py` prints `no changes` when all pins already match upstream.
